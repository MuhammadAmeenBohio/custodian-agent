# Custodian

[![CI](https://github.com/MuhammadAmeenBohio/custodian/actions/workflows/ci.yml/badge.svg)](https://github.com/MuhammadAmeenBohio/custodian/actions/workflows/ci.yml)

A governed AI agent for accounts payable. An LLM agent reads an invoice, checks the vendor and
**proposes** a payment. The agent never has authority itself: a policy service decides allow or deny
for every action, an audit log records every decision, and a sandbox executes the payment.

> **This is a reference implementation on synthetic data. It is not a production payments system.**
> No real invoices, bank details or company files are used anywhere. All IBANs start with `XX`,
> which is never a real country code.

## Status

Phase 0 (Foundation) covers the data layer only: Postgres with five isolated schemas, an object store,
50 labeled synthetic invoices rendered as images, and automated data checks. The agent, policy service
and audit log come in later phases.
## Prerequisites

- Docker Desktop (Compose v2)
- Python 3.12 and [uv](https://docs.astral.sh/uv/)
- GNU make (optional; every target is a one-line command you can paste instead)

## Quick start (PowerShell or bash)

```
cp .env.example .env          # PowerShell: Copy-Item .env.example .env
```

Edit `.env` and replace every `changeme` with a different password made of letters and digits only
(`$`, quotes and `#` break parsing). Then:

```
uv sync
make up                       # docker compose up -d
make seed                     # generate data, draw invoices, upload them, run the 8 data checks
make test                     # fast tests, no Docker
make test-integration         # needs the stack up and seeded
```

Expected: `make seed` ends with `8/8 checks passed`.

Do not edit `.env` while the stack runs. After changing a password: `make reset`, then `make up`.

## What `make seed` does

| Step | Script | Result |
| --- | --- | --- |
| 1 | `loader/generate.py` | 40 vendors, 49 bank accounts, 10 risk flags, ~350 historical payments, 50 invoices in Postgres; `eval/answer_key.jsonl` |
| 2 | `loader/render.py` | 50 PNG invoices in `generated/` (3 layouts, one carries a prompt-injection text) |
| 3 | `loader/upload.py` | PNGs in the `invoices` bucket as `synthetic/<id>.png`; `object_key` filled in |
| 4 | `loader/validate.py` | 8 Great Expectations checks |

The 50 invoices: 43 clean, 1 over the 10,000 USD threshold, 1 bank-details-changed, 1 duplicate,
3 blocked vendors, 1 prompt injection.
## Data sources

- **Synthetic data (used):** generated by Faker with seed 42, drawn with Pillow. Committed answer key
  in `eval/answer_key.jsonl`.
- **RVL-CDIP scans (not used by the project):** the `invoice_data/` folder, if present, holds real scanned
  business documents from Kaggle (`uditamin/rvl-cdip-small`, licence listed as unknown). They are
  gitignored, used for local experiments only, and never committed, uploaded, tested or demonstrated.

## Known limitations

- The object store runs **without authentication** in development. It publishes on `127.0.0.1` only.
- MinIO was replaced by SeaweedFS because MinIO community images are no longer published.
- All data is synthetic.
- Out of scope: hardware key management, real bank integrations, multi-currency and tax,
  production hardening.
- Dates are generated relative to the day you seed, so the "bank details changed in the last 30 days"
  case is always meaningful but the exact dates differ between days.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `password authentication failed` | The Postgres init script runs only on an empty volume. Fix `.env`, then `make reset` and `make up` |
| `port is not available` on 5432 | Windows reserves some ranges. This project uses 15432 (Postgres) and 18333 (object store) |
| `port is already allocated` | Another container holds the port. Check `docker ps -a` |
| Shell script errors inside containers | CRLF line endings. `.gitattributes` forces LF for `*.sh`, `Makefile`, `*.yml` |
| Tests cannot connect | The stack is down or `make up` has not finished. `docker compose ps -a`: Postgres `healthy`, `objectstore-init` `Exited (0)` |
| `.env` values seem ignored | Stale variables in your shell. Scripts and tests load `.env` with `override=True`, but check `$env:POSTGRES_PORT` |
| Integration tests fail on counts | Reseed: `make seed` |
